# 要件定義: GitHub 上で Claude に計画・実装を任せる

Issue: #4

## 目的

手元で Claude Code を開かなくても、GitHub の Issue 上で「計画 → 承認 → 実装 → PR」まで進められるようにする。計画・承認・決定事項を Issue に残し、あとから経緯を追えるようにする。

## 前提・制約

- 個人で開発している公開リポジトリで動かす。誰でも Issue やコメントを書ける
- 運用コストはゼロにする。Claude の認証には契約中のプラン（Pro/Max）のトークンを使い、従量課金の API キーは使わない
- GitHub Actions の上で、Anthropic 公式の Claude Code GitHub Actions を動かす
- 進め方は CLAUDE.md とスキル（`/start`、`/pr`）の決まりに従う。手元で `/start` を使う進め方も引き続き使える
- PR のマージは人が行う

## 用語

| 用語 | 定義 |
|---|---|
| 持ち主 | リポジトリの持ち主（yas0090）。Claude を動かせるのは持ち主だけ |
| 任せる Issue | `claude` ラベルが付いた Issue |
| 計画 | 変えるファイル、追加するテスト、方針をまとめたコメント |
| 承認 | 持ち主が、Claude の計画や仕様を受け入れて次へ進めてよいと伝えるコメント |
| プレビュー | PR の変更を反映したサイトを、本番とは別の URL で表示したもの |

## ユーザーストーリー

1. 持ち主として、Issue に `claude` ラベルを付けるだけで計画を出してほしい。思いついたときに、スマホからでも作業を始められるようにするため。
2. 持ち主として、計画や仕様をコメントで承認してから実装に進んでほしい。意図しない変更を防ぎ、判断の記録を Issue に残すため。
3. 持ち主として、計画に直してほしい点があればコメントで伝え、直した計画を出してほしい。
4. 持ち主として、画面を変える PR の表示を、手元でサーバーを立てずに確かめたい。
5. 持ち主として、他人に Claude を動かされたり、秘密情報を漏らされたりしないようにしたい。

## 受け入れ条件

### 計画と承認（US1, US2, US3）

- AC-1: 持ち主が Issue に `claude` ラベルを付けると、Claude が Issue を読み、計画を Issue にコメントする
- AC-2: `spec` ラベルも付いている場合は、計画の代わりに仕様を要件 → 設計 → タスクの順に作り、段階ごとに内容を Issue にコメントして承認を待つ。承認された仕様は、実装の PR で `docs/specs/` に書く（2026-10-27 変更: Issue からの実行のたびに新しいブランチが作られるため）
- AC-3: 持ち主が `@claude` を含むコメントで承認すると、次の段階へ進む。最後の段階（計画、または tasks.md）が承認されたら実装を始める
- AC-4: 持ち主が `@claude` を含むコメントで修正を依頼すると、計画や仕様を直し、直した内容を再度コメントする。承認と判断できないコメントでは実装を始めない
- AC-5: 承認されたときは、承認された内容と日付を Issue に記録として残す
- AC-6: 内容があいまいで計画を立てられないときは、推測で進めず、質問を Issue にコメントする

### 実装と PR（US2, US4）

- AC-7: 実装は `claude/<Issue番号>-<説明>` のブランチで行い、main へ直接コミットしない（2026-10-27 変更: Claude が作ったブランチだと分かるようにする）
- AC-8: 受け入れ条件に対応するテストを書き、型チェック・テスト・ビルドを通してから PR を作る。通らないときは PR を作らず、原因を Issue にコメントする
- AC-9: PR の本文は PR テンプレートに沿い、`Closes #<番号>` を含む。コミットメッセージは Conventional Commits 形式で、本文は日本語にする
- AC-10: Claude は PR をマージしない
- AC-11: 画面に関わるファイルを変えた PR には、変更を反映したプレビューの URL が PR に表示される。プレビューは本番のサイトに影響しない

### 安全（US5）

- AC-12: 持ち主以外がラベルを付けたり `@claude` を含むコメントを書いたりしても、Claude は動かない
- AC-13: Claude の認証トークンと、サイトで使う各 API キー（Twitch、YouTube、Cloudflare）は、Claude の出力・コメント・PR・プレビューに含まれない
- AC-14: Claude が動く環境には、作業に必要な権限（Issue と PR へのコメント、ブランチの作成と push）だけを与える

### 運用

- AC-15: Claude の実行が失敗したり時間切れになったりしたときは、そのことが Issue から分かる
- AC-16: 追加の費用がかからない（GitHub Actions は公開リポジトリの無料枠、Claude は契約プランの範囲で動く）

## 対象外（今回はやらない）

- PR のレビューを Claude に頼むこと（PR 上での `@claude` への応答）
- 持ち主以外のコラボレーターに Claude を動かす権限を与えること
- 複数の Issue を同時に進めること

## 決めていないこと（設計で決める）

- プレビューの出し方（Cloudflare Pages のプレビューを使うか、サイトデータをどう用意するか）
- Claude にワークフローファイル（`.github/workflows/`）の変更を許すか
- 承認と修正依頼の見分け方（決まった言葉にするか、Claude の判断に任せるか）
