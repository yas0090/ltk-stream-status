# 要件定義: LTK 出場者配信状況サイト

## 目的

LoL コミュニティ大会「League The K4sen（LTK）」の出場者が今配信しているか、その配信が LTK に関係するものかを、チームごとに一覧で確認できるようにする。

## 前提・制約

- 個人で作って公開する
- 運用コストはゼロにする（無料枠だけで動かす。有料サービスや有料ドメインは使わない）
- 出場者とチームの情報はリポジトリ内のデータファイル（JSON/YAML）で管理し、手で更新する
- 配信状態は定期実行で 5〜10 分ごとに更新する（リアルタイムでなくてよい。無料の定期実行基盤で生じる遅延は許容する）
- 対応する配信プラットフォームは Twitch と YouTube
- 公開 URL に、作者の GitHub のユーザー名を含めない（2026-10-26 追加）
- 出場チームは 4 チーム、1 チームは 15 人（3 階級 × 5 ロール）。1 チームの中で、同じ階級・同じロールの出場者は 1 人だけ

## 用語

| 用語 | 定義 |
|---|---|
| 出場者 | LTK に出場する選手。コーチやキャスターなどの選手以外は含めない |
| 階級 | チーム内での出場者の区分。Next / Core / Masters の3つ。1人の出場者はどれか1つに属する |
| ロール | 出場者の担当ポジション。TOP / JG / MID / ADC / SUP の5つ |
| チャンネル | 出場者が持つ Twitch または YouTube の配信チャンネル。1人が複数持つこともある |
| 配信中 | チャンネルのどれかでライブ配信が行われている状態。YouTube の配信予定（upcoming）とプレミア公開は含めない |
| LTK タグ | 配信タイトルにあらかじめ決めたキーワード（初期値は `LTK` のみ）が含まれる場合に付けるタグ |

## ユーザーストーリー

1. 視聴者として、チーム・階級ごとに出場者の配信状態を見たい。応援しているチームのメンバーが配信しているかをすぐ確認するため。
2. 視聴者として、配信が LTK に関係するものかをタグで見分けたい。大会関連の配信（スクリム、練習、本番など）だけを見るため。
3. 視聴者として、Twitch と YouTube のどちらで配信していても同じ画面で確認し、そのまま配信ページやチャンネルページを開きたい。
4. 視聴者として、チーム・階級・配信有無・LTK タグ有無を組み合わせて表示を絞り込みたい。
5. 視聴者として、表示中の情報がいつ更新されたものか、古くなっていないかを知りたい。
6. 管理者（自分）として、データファイルを編集するだけで出場者・チーム・チャンネルを追加・変更したい。
7. 管理者として、LTK 判定に使うキーワードをコードを変更せずに編集したい。
8. 視聴者として、見たい選手だけをチーム・階級・選手の単位で細かく選んで表示し、次に開いたときもその設定のままにしたい（2026-10-25 追加）。
9. 視聴者として、本戦の配信がある日はその配信をすぐ開きたい。本戦がない日は、次の本戦がいつかを知りたい（2026-10-26 追加）。
10. 視聴者として、特に追いかけている選手をお気に入りに登録し、絞り込みの条件を変えてもその選手の配信状態を見失わないようにしたい（2026-10-31 追加）。

## 受け入れ条件

### 表示（US1, US3, US5）

- AC-1: すべてのチームがチームごとに分かれて表示され、各チームに所属する出場者がすべて表示される
- AC-2: チームの表示順はデータファイルに書かれた順になる
- AC-3: チーム内では階級ごとに分かれて、Masters → Core → Next の順に表示される（2026-10-25 変更）
- AC-4: 階級内では出場者がロール順（TOP → JG → MID → ADC → SUP）に表示される
- AC-5: 配信中の出場者には赤い配信中マークが表示され、配信していない出場者には灰色のマークが表示される
- AC-6: すべての出場者に、登録されているチャンネルごとのチャンネルページへのリンクとプラットフォーム（Twitch / YouTube）が表示される
- AC-7: 配信中のチャンネルには、配信タイトルと配信ページへの直接リンクが表示される
- AC-8: 1人が複数のチャンネルで同時に配信している場合は、そのすべてが表示される
- AC-9: 配信状態の最終更新日時が画面に表示される
- AC-10: 最終更新日時から 30 分以上たっている場合、データが古いことを示す警告が表示される
- AC-11: スマートフォン幅（360px）でも横スクロールせずに閲覧できる
- AC-27: 各出場者に、登録したチャンネルのアイコン画像が表示される。アイコン画像を取得できなかった場合は、代わりの表示（名前の頭文字など）になり、レイアウトは崩れない（2026-10-25 追加）
- AC-42: 配信中の選手カードには、配信のサムネイル画像が表示される。配信していないときは、同じ大きさの枠に「OFFLINE」が表示され、配信状態が変わってもカードの大きさは変わらない（2026-10-26 追加）
- AC-28: チームごとに、LTK 公式サイトの CORE の色をチームカラーとしてカードに使う。チームカラーはデータファイルで定義する（2026-10-25 追加）
- AC-29: ロールは LoL 公式のポジションアイコンでも示す（2026-10-25 追加）
- AC-30: ページ下部に、非公式のファンサイトであることと、Riot Games の免責表示を載せる（2026-10-25 追加）。掲載内容の訂正・削除の依頼や不具合の報告を受ける連絡先（サイト専用の X アカウント）も載せる（2026-10-26 追加）

### タグ（US2, US7）

- AC-12: 配信タイトルに LTK キーワードのどれかが含まれる場合、その配信に「LTK」タグが付く。判定ではタイトルとキーワードの両方を Unicode NFKC 正規化して小文字にそろえてから比較する（大文字・小文字と全角・半角の違いを無視する）
- AC-13: どのキーワードも含まれない配信には「LTK」タグが付かない
- AC-14: LTK キーワードはデータファイルで定義されており、そのファイルを編集してリポジトリに反映すると、次の配信状態の更新から判定に反映される

### 絞り込み（US4）

- AC-15: 次の4つの軸で絞り込める
  - チーム（複数選択できる）
  - 階級（複数選択できる）
  - 配信有無（配信中のみ）
  - LTK タグ有無（LTK タグ付きの配信をしている出場者のみ）
- AC-16: 同じ軸の中で複数を選んだ場合は、どれかに当てはまる出場者が表示される（OR）
- AC-17: 異なる軸の条件は、すべてに当てはまる出場者だけが表示される（AND）
- AC-18: 絞り込みの結果、出場者が1人もいなくなったチームや階級は表示されない
- AC-19: 絞り込みをすべて解除すると、全員の表示に戻る

### 詳細フィルタ（US8、2026-10-25 追加）

- AC-31: 「詳細フィルタ」をモーダルで開き、チーム・階級・選手の階層で、選手ごとに表示・非表示を切り替えられる
- AC-32: チームや階級を切り替えると、配下の選手がまとめて切り替わる。配下の一部だけが非表示のときは、親の項目が「一部選択」の状態で表示される
- AC-33: 詳細フィルタで非表示にした選手は、簡易絞り込み（AC-15〜19）の条件に関係なく表示されない（簡易絞り込みと AND で組み合わさる）
- AC-34: 詳細フィルタの設定はブラウザに自動で保存され、次に開いたときに復元される
- AC-35: 詳細フィルタで非表示の選手がいる間は、その人数が絞り込み欄に表示される。モーダルの「すべて表示」で全員を表示に戻せる
- AC-36: ブラウザの保存領域が使えない環境（プライベートブラウズなど）でも、保存されないだけで詳細フィルタは動く
- AC-37: データファイルから選手がいなくなった場合、その選手の保存済み設定は無視される。新しく加わった選手は表示の状態で始まる
- AC-44: 簡易絞り込み（チーム・階級・配信中・LTK）の条件もブラウザに自動で保存され、次に開いたときに復元される。データファイルにないチームの条件は無視される。保存できない環境でも絞り込み自体は動く（2026-10-26 追加）

### ヘッダーと表示テーマ（2026-10-25 追加）

- AC-38: 画面上部に、スクロールしても常に表示されるヘッダーがあり、サイト名「LTK4 Live Now」（2026-10-26 変更。公開 URL に合わせた）、最終更新日時（AC-9）、表示テーマの切り替えが置かれている
- AC-39: 表示テーマはライトとダークを切り替えられる。初期値は OS の設定に関係なくライトで、選んだテーマはブラウザに自動で保存され、次に開いたときに復元される。保存できない環境でも切り替え自体は動く

### 本戦の案内（US9、2026-10-26 追加）

- AC-45: 本戦の日程（日付、ステージ名と Day、配信の開始時刻と終了予定時刻、対戦カード）は、データファイルで管理する。日程の追加・変更はデータファイルの編集だけで反映される
- AC-46: 本戦の当日 16:00 から終了予定時刻までは、ページの先頭（絞り込みの上）に本戦の案内を表示する。案内には、ステージ名と Day、開始時刻、対戦カード、公式 Twitch と公式 YouTube へのリンクを載せる
- AC-47: 案内を表示する時間帯は、公式チャンネルの配信状態も取得し、配信中なら「LIVE」を表示する。終了予定時刻を過ぎても公式チャンネルが配信中なら、案内を表示し続ける。本戦の日以外は、公式チャンネルの配信状態を取得しない
- AC-48: 案内を表示しない時間帯は、次の本戦の日付・ステージ名と Day・開始時刻を、ページの先頭に 1 行で表示し、その下に対戦カードを小さく並べる（2026-10-26 変更）。予定されている本戦がすべて終わったら、何も表示しない
- AC-49: 日付と時刻は日本時間で扱う。案内の表示・非表示は、データの更新を待たずに、ページを開いている端末の現在時刻で切り替わる
- AC-50: 各本戦で対戦カード（`games`）を省略または空にできる。そのときは本戦単位の `tiers`（階級の一覧）を書く（AC-45 の対戦カードは任意になる。2026-10-27 追加、#16）
- AC-51: `games` も `tiers` もない本戦はエラーにする。`tiers` に定義されていない階級を書いた場合も、`games` と本戦単位の `tiers` を両方書いた場合もエラーにする
- AC-52: 本戦の日程に、2026-11-21 Playoffs DAY 1 と 2026-11-22 Playoffs DAY 2 を加える。開始 10:00、終了予定 23:00（仮）、階級は Next・Core・Masters。対戦カードは決まったら書き足す
- AC-53: 対戦カードのない本戦では、当日の案内・次回の案内とも、対戦カードの代わりに階級（Next / Core / Masters）を表示する
- AC-54: 開始時刻が 16:00 より前の本戦は、AC-46・AC-47 の「当日 16:00」を開始時刻に読み替える（案内の表示と公式チャンネルの取得を開始時刻から始める）。16:00 以降に始まる本戦は今までどおり 16:00 から
- AC-55: 対戦カードのある本戦の表示と判定は変わらない

### 更新履歴（2026-10-31 追加、#24）

公開中のサイトに機能追加や不具合の修正を入れたとき、何が変わったかを閲覧者が確かめられるようにする。

- AC-56: 更新履歴は `data/changelog.yaml` に手で書く。1 件は日付・種類（新機能／改善／修正）・本文からなる
- AC-57: 日付の形式や実在、種類、本文（空）、定義外のキーに誤りがあればデータの検証でエラーになり、デプロイされない
- AC-58: ヘッダーの右側に「更新履歴」のボタンを置き、押すとモーダルで更新履歴を表示する
- AC-59: 項目は新しい順に全件並べ（同じ日付はファイルに書いた順）、件数が多いときはモーダルの中でスクロールできる。各項目に日付・種類・本文を表示する
- AC-60: 閉じるボタンと Esc キーでモーダルを閉じられる
- AC-61: 更新履歴が 0 件（または `changelog.yaml` がない）のときは、ボタンを表示しない
- AC-62: スマートフォンの幅でもモーダルが画面からはみ出さない
- AC-63: PR テンプレートの「確かめたこと」に、閲覧者に関わる変更なら `data/changelog.yaml` に追記した、という項目を置く
- 対象外: 未読の印、新しい項目があるときの自動表示
- 最初の項目は、#19 の修正（#20 のマージ日 2026-10-28）。個人名・チャンネル名は書かない

### お気に入り選手（US10、2026-10-31 追加、#23）

よく見ている選手の配信状態を、チーム一覧から探さずにすぐ確かめられるようにする。お気に入りに登録した選手を、ページ上部の専用の欄にまとめて表示する。

Issue では AC-56〜と書いたが、AC-56〜63 は更新履歴で使用済みのため、AC-64〜76 とする。

ボタン
- AC-64: 選手カードに星のボタンがある。お気に入りでないときは灰色、お気に入りのときは塗りつぶした星で表示する
- AC-65: ボタンを押すと、お気に入りの登録と解除が切り替わる
- AC-66: ボタンは、押した状態かどうかを `aria-pressed` で読み上げ環境に伝える

お気に入り欄
- AC-67: お気に入りが 1 人以上いるとき、フィルタの上にお気に入り欄を表示する（並びは お気に入り欄 → フィルタ → チーム一覧）。0 人のときは表示しない（2026-10-31 変更: フィルタの効く範囲がチーム一覧だと分かるよう、フィルタを一覧のすぐ上に置く）
- AC-68: お気に入り欄の選手は登録した順に並ぶ。解除して再登録した選手は末尾に並ぶ
- AC-69: お気に入り欄のカードは、チーム一覧と同じ構成で、その選手のチームカラーで表示する
- AC-70: お気に入り欄は、簡易絞り込み（チーム・階級・配信中のみ・LTK のみ）と詳細フィルタの非表示の影響を受けない。配信状態にかかわらず表示する
- AC-71: お気に入りの選手は、チーム一覧からは消えない（両方に表示する）
- AC-72: お気に入り欄とチーム一覧のどちらのボタンで登録・解除しても、両方の表示が揃う

保存
- AC-73: お気に入りはブラウザ（localStorage）に登録順で保存し、再読み込みしても残る。サーバーには送らない
- AC-74: 保存領域が使えない環境でも、エラーにならずにその場ではお気に入りが使える
- AC-75: 保存された値の形式が違うときは、お気に入りを空として扱う
- AC-76: 今のデータにいない選手のお気に入りは表示せず、保存からも取り除く
- 選手のキーは詳細フィルタの非表示と同じ `チームID:選手名`。大会中は選手がチームを移らない前提なので、移籍への対応はしない

### ヘルプ（2026-10-31 追加、#25）

自動表示
- AC-77: 初めて訪れたとき、ヘルプのモーダルを自動で表示する
- AC-78: 閉じたら localStorage に記録し、次の訪問からは自動で表示しない。表示しただけでは記録しない
- AC-79: 保存領域が使えない環境（読めない、書けない）では、自動で表示しない
- AC-80: ヘルプの内容を変えても、閉じたことのある閲覧者に自動で再表示しない（記録は内容のバージョンを持たない）

ボタン
- AC-81: ヘッダーの更新履歴ボタンの隣に「?」のボタンを置き、押すといつでもヘルプを表示する。更新履歴が 0 件でも常に出す
- AC-82: ボタンの読み上げ名は「ヘルプ」とする

内容
- AC-83: 1 枚のモーダルに、見出し付きで次の項目を縦に並べる。長いときはモーダルの中でスクロールできる: サイトの概要、選手カードの見方、フィルタの使い方、お気に入りの使い方、本戦スケジュール（1 行程度）
- AC-84: 説明は文章と、画面で使っている実際のアイコン（星、LIVE、配信サービス）で示す。スクリーンショットは使わない
- AC-85: 文章はコードに直接書く
- AC-90: 「選手カードの見方」に、配信中の選手カードのサンプルを画面と同じ描画で表示する。サムネイルはサンプル用の画像（コードに埋め込む）とし、リンクやボタンは操作できない。星も表示し（押しても反応しない）、カードを枠で囲んで見せる
- AC-92: ヘルプの見出しは帯と左の太線で目立たせ、見出しの上の余白を広げる。文章は文節の区切りで改行する
- AC-91: 「フィルタの使い方」の文言は画面の名前に合わせる（「絞り込み」のチーム・階級・配信（配信中、LTK）、「解除」、「詳細フィルタ」）。画面の名前を変えたときはヘルプも直す（2026-10-31 変更。「簡易絞り込み」「〜のみ」は画面にない表記だった）

操作
- AC-86: 閉じるボタンと Esc キーでモーダルを閉じられる
- AC-87: スマートフォンの幅でもモーダルが画面からはみ出さない
- AC-88: データの再読み込みで、開いているモーダルが閉じない
- AC-89: ボタンから開いて閉じたときも記録する（冪等）

### データ更新（US6）

- AC-20: 出場者（名前・チーム・階級・ロール）、チーム、チャンネルのデータファイルを編集してリポジトリに反映すると、次の配信状態の更新以降のサイトに反映される
- AC-21: 配信状態は定期実行によって自動的に更新される。実行間隔の設定は 10 分以内とする（実行基盤による遅延は許容する）。定期実行は、時刻どおりに動く外部のスケジューラーから 5 分ごとに起動する（2026-10-26 変更: GitHub Actions の schedule は大きく間引かれ、1 日に数回しか動かなかったため）。Twitch の配信状態と、配信中の YouTube の配信が終わったかどうかは毎回確認する。YouTube の新しい配信の確認は、AC-43 の予算に応じて間隔を広げることがある
- AC-22: 一部のチャンネルで情報を取得できなかった場合でも、ほかのチャンネルの状態は正常に表示され、取得に失敗したチャンネルは「取得失敗」と表示される
- AC-40: YouTube の RSS を取得できなかったチャンネルは、YouTube Data API で動画一覧を取り直して配信状態を判定する。API でも取得できなかった場合だけ「取得失敗」と表示する（2026-10-26 追加: 特定の時間帯に RSS がほぼ全チャンネルで 404 になったため）
- AC-43: YouTube Data API の 1 日の使用量（クォータ）が上限を超えないように、使用量を数え、使用量に応じて朝・昼の新しい配信の確認の間隔を広げる。上限を超えた応答を受けたら、リセットまで新しい配信の確認を止め、配信中の配信の終了チェックだけを続ける（2026-10-26 追加）
- AC-23: データファイルに次の誤りがある場合、更新処理はエラーで知らせ、サイトは前回の正常な状態のまま残る
  - 必須項目（出場者の名前・チーム・階級・ロール、1つ以上のチャンネル）が欠けている
  - 階級・ロールが定義外の値になっている
  - 1 チームの中で、同じ階級・同じロールの出場者が 2 人以上いる

### 運用コスト

- AC-24: 有料の API、ホスティング、データベースを使わずに、すべての機能が動く
- AC-25: 通常の運用で、利用する API の無料枠（1日あたりの上限など）を超えない
- AC-26: API キーなどの秘密情報が、公開リポジトリや配信されるファイルに含まれない
- AC-41: 公開 URL に GitHub のユーザー名が含まれない。移行前の GitHub Pages は公開を停止する（2026-10-26 追加）

## 対象外（今回はやらない）

- 試合結果、順位表、試合日程の表示
- 配信の埋め込み再生（リンクで外部サイトに移動する）
- 視聴者数、配信カテゴリ（ゲーム名）の表示（チャンネルのアイコン画像は AC-27、配信のサムネイルは AC-42 で表示する）
- 出場者データの管理画面（データファイルを直接編集する）
- 通知機能（配信開始時のプッシュ通知など）
- Twitch と YouTube 以外のプラットフォーム
- 選手以外の関係者（コーチ、キャスターなど）の表示
- 過去の配信履歴（最後に配信した日時など）の表示。現在配信しているかどうかだけを表示する
- 過去の大会のデータ。今回の大会のデータだけを扱う
- 絞り込み条件の URL での共有、端末をまたいだ詳細フィルタの共有

## 決定事項

- 本戦の日程は、公式の告知画像（Regular Stage、Masters Cup）から書き写す。開始時刻は Regular Stage（Next・Core）が 18:00、Masters Cup が 17:00 の予定。終了予定時刻は告知にないため、仮に 23:00 とする（2026-10-26）
- Playoffs の日程は未発表のため、発表されたらデータファイルに追加する（2026-10-26）

- 表示するのは選手だけにする
- LTK キーワードの初期値は `LTK` だけにする
- 表示するのは現在の配信状態だけにする（最後に配信した日時は表示しない）
- 扱うのは今回の大会のデータだけにする
- 表示はチーム → 階級（Masters → Core → Next）→ ロール（TOP → JG → MID → ADC → SUP）の順に分ける
- 1 チームの中で、同じ階級・同じロールの出場者は 1 人だけとする
- 絞り込みは軸の中は OR、軸の間は AND で組み合わせる
- YouTube の配信予定とプレミア公開は配信中に含めない
- 更新間隔は無料の定期実行基盤の遅延を許容し、データが古くなった場合は警告で知らせる
