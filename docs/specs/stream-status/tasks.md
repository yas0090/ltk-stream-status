その後、YouTube のクォータの節約と、使用量に応じた間隔の調整（AC-21 を変更、AC-43 を追加、design.md「YouTube のクォータ管理」）を加えた。

- [x] 9-1. 前回の結果（`state.json`）の読み込みと出力を作る（AC-43）

  - テスト: 読み込み・形式違い・読めないとき、出力の内容
- [x] 9-2. YouTube の取得を「終了チェック」と「新しい配信の確認」に分ける（AC-21, AC-40）
  - 前回配信中の動画 ID は毎回 `videos.list` で確かめる（節約 A）。新しい配信の確認では、RSS に失敗したチャンネルを `playlistItems.list` で取り直す
  - テスト（モック）: 終了チェック、RSS 失敗 → API で判定、API も失敗 → error、配信中のチャンネルは RSS を呼ばない
  - 実データで、アップロード再生リストに配信中の動画が載ることを確かめる
- [x] 9-3. アイコン画像の取得を 1 時間に 1 回にする（節約 B）

- [x] 9-4. 使用量を数え、予算に応じて新しい配信の確認の間隔を決める（AC-43）

- [x] 9-5. Cloudflare の準備（ユーザーが行う。手順を案内する）
