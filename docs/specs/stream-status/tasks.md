# タスク: LTK 出場者配信状況サイト

要件: [requirements.md](requirements.md) / 設計: [design.md](design.md)

各タスクはテストを先に書き、テストが通ったら完了とする。

## 1. プロジェクトの土台

- [x] 1-1. プロジェクトを初期化する
  - git init、package.json、TypeScript、Vite、Vitest、happy-dom、zod、yaml、tsx を入れる。Node は mise で 24 に固定する
  - `.gitignore` に `node_modules/`, `dist/`, `tmp/`, `.env*` を入れる
  - `npm test` と `npm run build` が空の状態で通ること
- [x] 1-2. ディレクトリ構成を作る（`data/`, `src/shared/`, `src/fetch/`, `src/web/`, `tests/`）

## 2. 共有ロジック（`src/shared/`）

- [ ] 2-1. 型と定数を定義する（階級、ロール、プラットフォーム、`SiteData`）
- [ ] 2-2. データファイルのスキーマと検証を作る（AC-23）
  - テスト: 欠けた項目、定義外の階級・ロール、同じ階級・ロールの重複、チーム ID の重複、チャンネルの重複、YouTube のチャンネル ID の形式
- [ ] 2-3. LTK 判定を作る（AC-12, AC-13）
  - テスト: 大文字・小文字、全角・半角（`ＬＴＫ`）、キーワードが複数ある場合、含まない場合
- [ ] 2-4. 並び替えを作る（AC-2〜4）
  - テスト: チームはデータの順、階級は Next → Core → Masters、ロールは TOP → JG → MID → ADC → SUP
- [ ] 2-5. 絞り込みを作る（AC-15〜19）
  - テスト: 各軸だけの場合、同じ軸の中の OR、軸の間の AND、空になったチームと階級を消すこと、解除で全員に戻ること
- [ ] 2-6. データが古いかの判定を作る（AC-10）
  - テスト: 29分59秒なら警告しない、30分ちょうどなら警告する

## 3. 配信状態の取得（`src/fetch/`）

- [ ] 3-1. Twitch の取得を作る
  - アプリトークンの取得、`/helix/streams` を 100 件ずつ呼ぶ処理、live / offline の判定
  - テスト（fetch をモックする）: 配信中・配信していない人が混ざる場合、100 件を超える場合、リクエストの失敗で `error` になること（AC-22）
- [ ] 3-2. YouTube の取得を作る
  - RSS の取得と解析、7 日以内の動画への絞り込み、`videos.list` を 50 件ずつ呼ぶ処理
  - 配信中の判定: `live` かつ `P0D`。配信予定とプレミア公開は除外する
  - テスト（モック）: 配信中、配信予定、プレミア公開、同時に複数配信（AC-8）、RSS の失敗、API の失敗（AC-22）
- [ ] 3-3. site-data.json の生成処理を作る
  - データファイルの読み込み → 検証 → 取得 → LTK 判定 → 出力。検証に失敗したら終了コード 1 で終える
  - 結合テスト: データファイルやキーワードを変えると出力に反映されること（AC-14, AC-20）、検証エラーで終了コード 1 になること（AC-23）
- [ ] 3-4. 実際の API で動作を確かめる（手動）
  - 自分で用意した Twitch と YouTube のキーを `.env` に置き、ローカルで実行する
  - YouTube の配信予定・プレミア公開・配信中を、実データで正しく判定できることを確かめる（design.md のリスク項目）
  - 確かめた結果、設計と違う点があれば design.md を先に更新する
