# Issue を作る

1. 種類を決める
   - 機能追加・改善 → `.github/ISSUE_TEMPLATE/feature.yml` の項目（目的、ユーザーストーリー、受け入れ条件、補足）
   - 不具合 → `.github/ISSUE_TEMPLATE/bug.yml` の項目（再現手順、期待する動き、実際の動き、環境）
   - 運用作業 → 目的と、終わったと判断する条件をチェックリストで書く
2. 内容が足りなければ、推測で埋めずにユーザーに聞く。特に受け入れ条件は確かめられる形で書く
3. ラベルを決める
   - `enhancement` / `bug` / `ops` のどれか
   - データモデル・画面構成・外部 API の変更を含む、または受け入れ条件が多い場合は `spec` も付ける
   - 関連する仕様書があれば、補足に `docs/specs/` へのリンクを書く
4. タイトルは日本語で、何をするかが分かる一文にする
5. タイトル、本文、ラベルをユーザーに見せ、承認を得てから作る

```sh
gh issue create --title "<タイトル>" --label "<ラベル>" --body-file <本文のファイル>
```

本文のファイルはスクラッチパッドに置く。作ったら Issue の URL を伝える。
